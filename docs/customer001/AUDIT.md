# CUSTOMER_001 实装审计

基线 ce90da4。保留 Phaser + TypeScript + Vite、现有地图、自动客流、三个同时在店的容量、队列、左右进出动线、一次性结账、经营账本、浮动摇杆、独立营业按钮和作者工作台。

可复用：`world.ts` 的逐步碰撞和动态避让、`customer-flow.ts` 的计划/访客、`NarrativeRecord.profiles` 的来访次数与事件标记、同一经营快照和未知字段保护、现有肖像对话浮层。

缺口与最小实现：

- 商品仅 milk / bread / rice，没有谷物、种子、密封袋和容器。用现有面包货位作高度机制原型，偏好分类保留在 NPC 数据中，不伪造新商品或更名现有库存。
- 原对话只有测试熟客，新增 NPC 对话池作为同一 Narrative 的分支，不创建第二套关系数据库。
- 宿舍仅有楼梯预留入口，未发现收藏页、摆放系统和双版本素材管线。建立候选收藏品数据及两份独立占位资源，不创建背包物品、不赠送、不声称宿舍功能已实现。
- 作者工作台当前编辑测试熟客配置；本轮仓鼠配置单独 JSON 驱动，不假装其已支持所有 NPC 表单。

正常日从第二天起按动态权重（基础 0.28、调整货位后 0.42、较久未到店加权，封顶 0.65）决定是否安排一位仓鼠，安排在非首位保留原测试熟客。计划中的身份与时间保存，刷新不重抽；不是每天必来。不根据任何权重推断搬家、职业或室友关系。

开发预览 `?npc-preview=001`：独立经营键 `puppy-mart.npc001-preview.v1`、独立教程键，预置少量库存并让首位计划顾客为仓鼠；仍由开店后的自动客流进店。不会写正常经营/教程/名字存档，不提供正式游戏手动召唤按钮。刷新继续这个预览，清理仅该预览键可重新验证首次事件。

本轮不运行发布脚本，不更新 gh-pages，不部署正式站点。
