# 角色001与世界观约束 v2.1

本文件记录作者补充，保留已有 P0 经营流程。新设定取代早期「继承旧店」的主角背景；不据此扩写正式剧本。

## 角色001：玩家命名的吉娃娃

刚毕业，求职不顺，于是到街角便利店兼职。原老板突然跑路，拖欠工资，留下经营困难的便利店。店长为了追回劳动所得，也因暂时没有更好的去处，决定尝试经营商店。

性格：急于求成、容易焦虑、思绪活跃、计划很多、经常高估同时处理事情的能力；具有明显的中性、非传统性别表达气质。来自相对保守的小城市，是 LGBTQ+ 群体的 ally。

不得推断其性别身份、性取向或代词偏好。中文叙述暂用「它」或「店长」；这不构成角色已经自选了代词。首次营业前由玩家命名，不提供默认名字、不要求选择性别。名字以独立 `puppy-mart.player-profile.v1` 键保存在本机；不读取、删除或迁移任何旧经营存档，不代表云同步。可在刷新后的首页修改名字，修改不影响经营数据。P0 经营分数仍不持久保存。

## 酷儿友好创作原则

表达应自然、细腻、日常化。允许低调彩虹标识、不按性别划分服装和装饰、多样的亲密关系与家庭结构、角色自选名字和称呼、不同的身份归属理解及日常酷儿经验。

禁止刻板印象；不默认异性恋或顺性别；不猎奇化身份；不将所有酷儿故事写成悲剧；不自动编写出柜剧情；不强制玩家选性别；不通过广告解锁身份认同剧情。

所有正式故事、对白、日记、主线文字由作者编写。开发者只搭建结构，必要占位必须标明「待作者填写」。不得自动生成、改写或发布正式文本。正式文学内容与作者工作台仍属于后续 P2。

## 数据边界

`src/characters.ts` 定义角色 ID 以及全部可选字段：`preferredName`、`pronouns`、`relationshipNotes`、`identityNotes`、`authorNotes`。不要求填满，不默认公开。`publicCharacter` 仅投影 ID 与明确提供的使用名字，备注与代词不会自动展示。

`content/author/character-001.json` 为内部设定源，未被运行时代码导入，Vite 默认不会复制进 `dist`。不能把作者源文件放入 `public/` 或直接传给玩家 UI。仓库本身的访问权限仍决定谁能读取作者文件：内部字段隔离不等于仓库加密。未来作者工作台必须区分内部笔记与作者明确批准发布的文本。

## 场景配置

`src/data/store-style.json` 提供以下预留：

| 配置 | 当前效果 | 后续扩展 |
| --- | --- | --- |
| counterSticker | 收银台低调六色贴纸，可关闭或改位置、大小、颜色 | 替换贴纸资产 |
| wallPoster | 默认关闭的墙面矩形占位，可改位置、大小、颜色 | 作者批准的海报资产 |
| managerOutfit | 上衣、围裙配色，无性别分类 | 服装资产与选择界面 |
| holidayDecoration | 默认关闭的装饰占位 | 节日主题资产 |
| relationshipProp | 默认关闭的道具占位，contentId 为空 | 作者批准后绑定互动内容 |

上述槽位仅配置驱动视觉，不意味着已经实现换装商店、节日事件或人物互动剧情。改 JSON 后重新构建；不在限时营业中弹出故事。不得凭 contentId 自动生成关系或身份文本。
