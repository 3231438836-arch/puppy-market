# P2-01｜第一个可测试切片：保底首遇与独立回访调度

基底：P2-00 `e27e51b`（PR #1，尚未合并）。独立分支 `feature/p2-01-hamster-scheduling`；后续 PR 必须以 #1 的分支为 base，不能重复把 P2-00 报为本批修改。

## 源码缺口

当前 PR #1 基线只有单一测试熟客 Narrative、普通兔子纹理、每日固定4人且第一位固定测试熟客。没有正式仓鼠注册、独立货架或家具安装系统。另一个未合并的 v0.7.1 工作区已有仓鼠临时美术，允许复用美术，不整体覆盖当前分支。

## 本切片

- 第2天新计划必含一位 CUSTOMER_001；旧第4天及以后未见的档案在下一营业日补登场；既有当日计划不重排、不插队、不重复到店。
- 后续按权重及最短间隔调度，可能不来；普通生产计划不再固定召唤测试熟客。保留已存的测试熟客、活动对话和作者工作台。
- 仓鼠复用现有 Visitor/购物/排队/收款状态机、Narrative 档案与活动对话；在真实到达高货架时触发一次求助事件，保留跳过与刷新恢复。采用仓鼠独立临时像素美术，标明未定稿。
- 首次求助候选对白在此前指令仍标注 draft，Issue #2 仅确认事件、不提供批准的新首遇原文。保留候选来源为草案，运行时先用明确的功能占位，不自行写正式对白。
- 矮架翻新回访的数据/条件接口必须区分购买、安装、真实可达、不同来访；本基底没有安装系统，默认条件为 false。本切片不伪造矮架、不按日期认定翻新。真正家具条件与端到端翻新回访留待 #4 接通，不能把整个 Issue #2 标为全部完成。

## 修改范围

`customer-flow.ts`（计划身份）、`narrative.ts`（复用多角色注册/一次性事件/去重来访）、`world.ts`（调度、货架事件挂点）、`persistence.ts`（旧档下次首遇日期）、`scene.ts`/`app.ts`（临时仓鼠美术与肖像）、独立角色事件配置、单元/浏览器用例。不做 #3、#4、#5、#6。

## 存档迁移

原键/root version1 不变；Arrival.customerId 可选（旧计划仍有效）；特殊档案新增可选 firstDueDay，旧 active 节点仍由其原注册表读取。新档初次保底为2；旧档已有第2天及以后且未遇见，恢复时设置 next day due，不改变当前计划/库存/资金。来访在实际进门时计数，以 visitor ID 防重；读取/打开对话不算新来访。

## 验收用例

1. 新局第2天，多种随机输入始终恰好一个仓鼠；第1天不强制特殊角色。
2. 旧第4天未见：现有名单不变，次日首遇；已见不会再次保底/重播。
3. 普通计划没有无条件测试熟客；旧显式测试顾客与活动对话兼容。
4. 首次到高架→占位求助→继续/跳过→取货→排队→一次收款→离店；刷新与重复回调不重复来访/事件。
5. 后续普通回访遵守间隔和权重；无实际已安装可达矮架，翻新对白永不播放；同一来访不能先首遇再翻新。
6. 320px/390px 肖像与按钮可读可触控；build、npm test、npm run test、完整浏览器回归。
