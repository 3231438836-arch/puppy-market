# 可选激励视频基础架构（真实广告未开启）

本轮仅完成平台无关服务和明确标识的开发模拟。没有生产广告位、SDK初始化、后台登录、上传或正式部署。普通网页入口不会访问 `tap`、`tt`、`wx`。

## 奖励与经营

配置：`src/data/ad-rewards.json`。全局及各环境默认关闭，全部广告位为 null。

- 普通进货优惠券：1张，下一次在仓库点击用券采购时补贴1金币；可选择原价保留券。普通3件整箱采购适用；不改变商品售价、库存成本或经营利润。补贴单独列出，现金按净额减少。
- 旧物小盲盒：木片50%、布料30%、颜料20%，一次1份普通材料；不包含剧情礼物。材料持久化已实现，装饰制作/摆放用途尚未实现。
- 每游戏日每类1次、合计2次；数量、权重、上限可配置。金币奖励本轮关闭且隐藏。

不以广告限制基础营业、剧情、特殊顾客帮助或包容性设施。

## 服务与持久化

`RewardedAdService` 负责加载、播放、完成、提前关闭、失败、无填充、超时与中断状态。平台提供者只返回结果，场景不直接操作SDK。

点击先保存唯一事务及待发奖励；收到完整观看凭据后，将收据、次数、奖励库存及资金以一次完整存档写入。busy、防重事务ID、版本比较与已发收据共同防止重复点击/回调发奖。保存失败不增加奖励；刷新清除未完成事务，不推断观看成功；超时解除控制。旧存档缺少广告字段时使用安全空值。

这是本地存档一致性保护，不是服务器防作弊或平台收入验证。清除浏览器数据、修改本地存档、多个标签页并发经营等不属于可信服务器账本保证。

## 官方文档已确认 / 尚缺

依据用户上传的《广告接入指南》《激励视频广告》HTML：

- 文档接口为 `tap.createRewardedVideoAd({ adUnitId })`；组件是单例。
- 文档列出 `load()`、`show()`、`onLoad`、`onError`、`onClose`。
- 仅 `onClose` 的 `res && res.isEnded === true` 代表完整观看。`show()`成功仅代表展示成功，不能发奖。
- `taptap-contract.ts` 仅实现上述严格结果判断，没有调用真实SDK。

尚需官方确认当前 **H5** 运行容器的SDK导入与初始化、可用性探测、单例多广告位生命周期、监听解除方式、错误码与无填充映射、测试广告识别及账号审核要求。当前未实现真实提供者，不能声称测试广告已播放或已产生收益；不能据CLI文档推断运行时广告接口。

后台需由开发者在游戏的「商店 → 小游戏广告」核对申请开通，并在官方控制台完成认证、财务主体及收款信息。不要将敏感资料或密钥放入前端或聊天。需取得真实测试/正式激励视频广告位ID（优惠券、盲盒分别配置，可否共用需后台确认），配置保持分离，待真实H5 SDK和测试配置齐备后再接真实提供者。实际开通资格、审核与收益结算以后台最新要求为准。

真实收益需要广告功能获准、正确生产广告位、平台有效展示/观看及结算规则；本地模拟、测试模式、客户端发奖均不证明真实收益。

## 运行开发模拟

```sh
npm ci
npm run dev -- --host 0.0.0.0
```

打开 `http://localhost:5173/?ads-test=1`，进入游戏 → 库存 → 可选视频奖励。手机使用同局域网电脑IP（该地址不是公网试玩链接）。选择奖励后可明确模拟完整观看、提前关闭、加载失败和无填充。

界面明确标记「开发模拟广告」「没有真实视频」「不产生真实广告收益」。独立使用 `puppy-mart.ad-test-session.v1` 和独立教程键；不写普通经营存档或玩家名称。DEV动态导入，生产构建不包含模拟提供者，生产访问此查询参数不会开启模拟。模拟收据标记 `development-test`。
